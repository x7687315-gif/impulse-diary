# 阶段 10：目标基金「结转一致性」修复（v0.3.1）

日期：2026-10-04 ｜ 需求来源：用户真机反馈 —— 「目标一达成后建了目标二，侧边栏里第一个目标没显示已完成，灵动岛上却显示达到了」

## 一、问题与根因

**现象**：灵动岛大件基金显示「攒够了、达标了」，我的目标页里对应目标却显示未达成。

**根因**：不是显示逻辑写错（两处用的是同一个推导函数 `fundInOf`），而是**钱的归属在目标生命周期变化时断链了**：

1. 删除目标时，已存入该目标的钱（`fundAmount > 0` 且 `targetId` 指向它）会变成**孤儿账**——
   灵动岛胶囊的总额口径（无 targetId 过滤）把孤儿钱照算，看起来「攒够了」；
   目标页按目标过滤，孤儿钱不计入任何目标 → 显示「还差 ¥X」。
2. 记录表单的默认存入目标固定为**第一个**目标——即使它已经达成，新省下的钱仍默认流进去，
   加重「岛上一个数、页面另一个数」的困惑。

## 二、怎么修的

1. **删除目标 = 结转**（根治孤儿账）：删除时有已存金额且存在其他进行中目标时，
   弹窗直接询问「把已存的 ¥X 转入「目标二」吗？」——确认后把指向旧目标的所有记录与
   FUND 调整流水的 `targetId` 批量改指新目标（`where('targetId').equals(...).modify(...)`），
   金额原封不动结转；选「不转」才会变为未分配（弹窗明确告知后果）。
2. **胶囊口径改为「只计进行中目标名下的钱」**：`大件基金 ¥X / ¥Y` 的分子分母都只统计
   ACTIVE 目标，与目标页的每目标进度天然一致，永远不会出现两套数字。
3. **未分配钱显性化**：基金明细面板新增「未分配（原目标已删除）」行，钱去了哪一目了然。
4. **表单默认目标改为最新创建的目标**：符合「完成一个阶段 → 开启下一阶段」的心智模型，
   新省下的钱默认流向当前阶段，而不是已经达成的旧目标。

## 三、怎么完成的（验证记录）

无头 Chrome 完整复现用户操作序列（目标一 ¥300 → 记两笔忍住 ¥100 使其达成 → 建目标二 ¥200 →
删除目标一并选择转存）：

| 检查项 | 结果 |
|--------|------|
| 目标页 goal2 | ¥333 / ¥200，显示「已达成 · 可以真正拥有它了」✓ |
| 灵动岛大件基金胶囊 | ¥333 / ¥200，与目标页**完全一致** ✓ |
| 基金明细面板 | 无「未分配」行（¥333 全部结转）✓，含新目标进度条 ✓ |
| 构建 | tsc 0 错误，vite build 通过 ✓ |
| 安全扫描 | 令牌 0 / 危险 API 0 / 外部网络请求 0，无新增依赖 ✓ |

## 四、边界说明

- 转存只改 `targetId` 归属，**不动任何原始记录的内容与金额**——日记流保持完整可审计。
- 若删除的是唯一目标（无其他进行中目标），钱按原样保留为未分配，重建目标后可用
  「手动调整 → FUND」重新分配；面板的未分配行会一直提示，不会让钱凭空消失。
