# 阶段 11：目标基金「瀑布式自动分配」（v0.4.0）

日期：2026-10-04 ｜ 需求来源：用户澄清 —— 「目标按时间顺序排列，完成一个，钱自动归到第二个；增删目标是用户的事；这样能一直累积，看到省下的钱究竟买了什么」

## 一、做了什么

**基金分配模型重构：从「手动选目标」改为「瀑布式自动分配」**（数据模型层面的升级）：

1. **钱 = 总池，不再绑定单个目标**。每笔省下的钱进入基金总池，按目标的创建时间顺序自动填充：
   先填满第 1 阶段目标 → 溢出自动流入第 2 阶段 → 第 3 阶段……
2. **记录表单去掉「存入哪个目标」下拉框**。存多少仍可自定义（默认全部），去向全自动。
3. **我的目标页 = 阶段时间线**：每个目标标注「第 N 阶段」，三种状态一目了然：
   - 已达成（这笔省下的钱变成了它）
   - 正在存入（还差 ¥X · 已完成 Y%）
   - 排队中（前面阶段达成后自动开始存入）
4. **灵动岛与明细面板同步改口径**：胶囊显示 `总池 / Σ目标额`；面板按阶段列出每级进度，
   标注「正在存」的是哪一级。
5. **达成更聪明**：存入前后各算一次池子水位，跨过达成线时提示
   「🎉「X」已达成！剩下的钱自动开始存入下一个目标」。
6. **v0.3.1 的删除转存逻辑回归简单**：删除目标不再需要转存——瀑布会自动重新分配，
   历史记录原样保留在日记里。

## 二、怎么做的

- **分配算法是纯推导，不落库**：`allocateFund(goals, pool)` 按创建时间顺序逐级填充
  （`allocated = clamp(pool - 前面各级目标和, 0, target)`），目标新增/删除/改金额后
  分配结果自动重算——不存在「孤儿账」这类持久化错误状态。
- **`targetId` 字段退役**：EntryForm / AdjustDialog 不再写入，数据库字段保留（无迁移成本），
  旧数据完全兼容（总池只看 `fundAmount` 与 FUND 调整，不看 targetId）。
- **负数调整天然支持**：手动调整输入负数（取出一笔）会降低总池水位，所有阶段的分配自动回退重算。
- **达成检测**：`fundPoolNow()` 在写库前后各取一次水位，跨线即触发达成提示。

## 四、边界说明

- 「阶段」顺序 = 目标创建时间顺序；编辑目标不改变顺序。
- 目标全部达成后，继续省下的钱进入「结余」，创建新目标时自动成为它的启动资金。
- 暂停（PAUSED）目标不参与瀑布分配。
